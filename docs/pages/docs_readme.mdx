# README conventions

Every board and package needs a root `README.md` that explains its purpose and
how to build or use it. Include only sections with useful content, not placeholders.

## Board README

Describe the main devices, interfaces, operating limits, and license. Give exact
build commands, with required tools or external assets listed first:

```bash
pcb build <BoardName>.zen
pcb layout <BoardName>.zen
```

Explain the output and expected warnings. Add pin assignments, design constraints,
firmware instructions, or datasheets when needed to use the board. Put versioned
rework and test procedures in [bringup documentation](/pages/docs_bringup).

## Package README

Identify public symbols and provide one complete import or instantiation example.
Document required inputs, defaults, units, limits, and layout constraints alongside
the example. Do not add a configuration section for a package with no configuration.

## Style

- Use direct instructions and consistent terminology.
- Put identifiers, file names, commands, and pin names in backticks.
- Number procedural steps; mention side effects and common failures when relevant.
- Keep examples current with the source. Remove repeated prose, historical plans,
  and implementation details that do not help the reader use the board or package.
